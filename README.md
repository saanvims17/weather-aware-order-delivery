## Overview

Unexpected weather conditions can disrupt deliveries and affect customer satisfaction.

The **Weather-Aware Order Delivery System** addresses this challenge by retrieving weather information for customer delivery locations and evaluating whether conditions may affect delivery operations.

When potentially disruptive weather is detected, the system marks the corresponding order as `Delayed` and generates a personalized apology message. Orders unaffected by the configured weather rules remain `Pending`.

The application also handles invalid city names gracefully, allowing the remaining orders to be processed without terminating the program.

## Key Features

| Feature | Description |
|---|---|
| 🌍 Real-Time Weather | Retrieves current weather conditions using the OpenWeatherMap API. |
| ⚡ Asynchronous Processing | Fetches weather information for multiple cities concurrently. |
| 🌧️ Weather-Based Decisions | Identifies `Rain`, `Snow`, and `Extreme` weather conditions as potential causes of delay. |
| 💬 Personalized Apologies | Generates customer-specific messages containing the customer's name, destination, and weather-related reason. |
| 📦 Order Management | Updates order statuses and stores relevant weather and message information in JSON. |
| 🛡️ Error Handling | Handles invalid city names and unsuccessful API responses without crashing the application. |
| 🔐 Secure Configuration | Loads the weather API key from an environment file instead of hardcoding it in the source code. |

## How It Works

<div align="center">

**Order Data (`orders.json`)**  
↓  
**Load Orders and API Configuration**  
↓  
**Fetch Weather for Each City Concurrently**  
↓  
**Evaluate Weather Conditions**  
↓  
**Is the Weather `Rain`, `Snow`, or `Extreme`?**

</div>

| Condition | Action |
|---|---|
| 🌧️ Rain | Mark the order as `Delayed` and generate an apology. |
| ❄️ Snow | Mark the order as `Delayed` and generate an apology. |
| ⛈️ Extreme | Mark the order as `Delayed` and generate an apology. |
| ☁️ Other conditions | Keep the order `Pending`. |
| ❌ Invalid city or API failure | Log the error and continue processing other orders. |

After processing, the application saves the updated order information to the JSON output file.

> **Note:** The application uses current weather conditions and a simplified delay policy. In a production system, delivery decisions would also consider forecasts, route conditions, delivery schedules, and other operational factors.

## Getting Started

### 1. Prerequisites

Ensure that you have:

- Python 3.10 or later
- An OpenWeatherMap API key
- Git installed
- An internet connection

### 2. Clone the Repository

```bash
git clone https://github.com/YOUR_USERNAME/weather-aware-order-delivery.git
cd weather-aware-order-delivery
```

Replace `YOUR_USERNAME` with your GitHub username.

### 3. Create a Virtual Environment

**macOS / Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

**Windows**

```powershell
python -m venv .venv
.venv\Scripts\activate
```

### 4. Install Dependencies

```bash
pip install -r requirements.txt
```

### 5. Configure the API Key

Create a file named `.env` in the project root:

```env
OPENWEATHER_API_KEY=your_api_key_here
```

Replace `your_api_key_here` with your actual OpenWeatherMap API key.

Ensure that `.env` is listed in `.gitignore`. **Never commit your API key to GitHub.**

If your application expects a different environment variable name, use the exact name referenced in `main.py`.

### 6. Run the Application

```bash
python main.py
```

The application will fetch weather information for the configured order destinations, evaluate the weather conditions, update order statuses, generate apology messages when necessary, and save the results.

## Weather-Aware Apology Function

The application uses a Python function to generate personalized customer notifications.

```python
def weather_aware_apology(customer_name, city, condition, description):
    weather_reason = {
        "Rain": description,
        "Snow": description,
        "Extreme": f"extreme weather ({description})",
    }.get(condition, description)

    return (
        f"Hi {customer_name}, your order to {city} may be delayed "
        f"due to {weather_reason}. We appreciate your patience!"
    )
```

This template-based approach generates messages using customer and weather information without requiring a separate LLM API call at runtime.

## Security and Reliability

- Keep API credentials in `.env`.
- Exclude `.env` and `.venv/` from version control.
- Handle HTTP errors and invalid locations gracefully.
- Avoid logging API keys or other sensitive configuration values.
- Validate the JSON data before processing it.
